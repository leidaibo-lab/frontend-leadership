# 价值证据台账模板

## 1. 使用目的

价值证据台账用于把管理工作从“做过什么”整理为“解决了什么问题、带来了什么变化、如何被证明、能否复制”。

适用于：

- 业务线负责人机制和组织扩展
- 工程底座、组件库、模板和监控建设
- 稳定性治理、质量改进和 P0/P1 复盘
- AI 研发流程治理和团队提效
- 招聘、梯队、授权和团队稳定性
- 述职、晋升、绩效、汇报和对外案例整理

记录原则：

1. 先记录事实，再写判断和价值，不用结果倒推过程。
2. 尽量记录变化前基线和变化后结果，避免只写绝对数量。
3. 活动数量只能作为过程证据，不能单独作为价值证明。
4. 明确本人贡献、团队贡献和外部条件，避免把团队结果全部归因于个人。
5. 每条证据都标注证据位置、可信等级和公开边界。

## 2. 单条价值证据卡

复制以下模板，每个关键事件单独建立一张记录卡。

```markdown
## [VE-YYYY-NNN] 价值证据标题

### A. 基本信息

- 记录编号：VE-YYYY-NNN
- 记录日期：YYYY-MM-DD
- 价值领域：组织治理 / 业务交付 / 工程底座 / 质量稳定性 / AI治理 / 人才梯队 / 其他
- 业务线或团队：
- 影响范围：个人 / 模块 / 业务线 / 多业务线 / 公司级
- 证据状态：草稿 / 待补证据 / 已验证 / 可对外使用
- 公开边界：内部可用 / 脱敏后可用 / 仅内部使用

### B. 问题与基线

- 背景：当时发生了什么，为什么需要处理？
- 目标：要解决的具体问题是什么？
- 变化前基线：
  - 交付：
  - 质量：
  - 成本或效率：
  - 组织或协作：
- 风险：如果不处理，可能造成什么影响？
- 基线证据：数据、记录或链接位置。

### C. 判断与取舍

- 我的关键判断：
- 为什么这样判断：
- 被放弃或延后的方案：
- 取舍依据：业务价值 / 风险 / 成本 / 时间 / 组织承接能力 / 其他

### D. 行动与责任

- 我负责的部分：
- 团队共同完成的部分：
- 关键动作：
  1. 
  2. 
  3. 
- 授权或协作对象：
- 使用的机制、模板或工程资产：
- 关键时间节点：

### E. 结果与证据

- 变化后结果：
  - 交付：
  - 质量：
  - 成本或效率：
  - 组织或协作：
- 结果指标：指标名 / 变化前 / 变化后 / 变化幅度 / 统计周期
- 结果证据：数据看板、发布记录、缺陷记录、监控截图、评审记录、用户反馈或其他可复核材料。
- 证据位置：链接、文档路径、系统名称或记录编号。
- 结果可信等级：
  - A：有明确基线、结果数据和第三方或系统记录。
  - B：有结果记录和多方反馈，但基线或统计周期不完整。
  - C：主要是个人观察或定性反馈，只能作为线索。

### F. 价值归因与可复制性

- 直接价值：

- 本人贡献边界：
- 可复制的方法：
- 复制前提：
- 适用范围：
- 不适用场景：
- 下一次改进：

### G. 审核与更新

- 事实核验人：
- 业务负责人确认：
- 最近复核日期：YYYY-MM-DD
- 后续待补证据：
- 是否已沉淀为 SOP、模板、工程资产或 Skill：是 / 否
```

## 3. 台账总表

总表用于快速查看所有证据卡的覆盖范围和质量，不替代单条证据卡。

| 编号 | 证据标题 | 价值领域 | 影响范围 | 基线 | 关键结果 | 证据等级 | 状态 | 公开边界 | 详情位置 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| VE-YYYY-001 |  |  |  |  |  | A/B/C | 草稿/待验证/已验证 |  |  |

建议至少覆盖以下价值领域：

- 组织：负责人机制、授权、副手、子业务线扩展
- 交付：周期、按期率、风险关闭、跨团队协作
- 工程：模板、组件库、工具库、监控、知识库复用
- 质量：缺陷、线上问题、复发率、评审和复盘闭环
- AI：流程覆盖、节省时间、返工变化、质量责任留痕
- 人才：新人接入、梯队承接、关键模块替补、负责人独立闭环

## 4. 季度价值汇总

每季度只选择 3 至 5 条证据进入汇总，避免把所有工作堆成工作清单。

## 5. 证据质量检查

每次季度汇总前逐条检查：

- 是否写清了问题，而不是只写完成事项？
- 是否有变化前基线？没有基线时，是否明确标注限制？
- 是否区分个人贡献、团队贡献和外部条件？
- 是否至少有一项可复核证据？
- 结果是否覆盖交付、质量、成本、组织或协作中的至少一项变化？
- 是否把会议次数、文档数量、分享次数误当成价值？
- 是否记录了方法复制的前提和边界？
- 是否完成脱敏和公开边界审查？

## 6. 推荐指标口径

不要为了填表强行造数据。优先使用能反映实际变化的指标：

| 领域 | 优先指标 | 常见辅助证据 |
| --- | --- | --- |
| 组织治理 | 负责人独立闭环比例、风险上浮周期、管理跨度、重复占用数 | 负责人会记录、矩阵检查、复盘记录 |
| 交付 | 新项目启动周期、按期交付率、返工周期、跨团队阻塞关闭周期 | 排期、发布记录、风险清单 |
| 工程底座 | 接入项目数、复用率、启动成本、新人接入周期、维护成本 | 模板仓库、组件库版本、接入记录 |
| 质量稳定性 | P0/P1 数量、重复缺陷、问题闭环率、复发率、监控覆盖 | Sentry、缺陷系统、复盘报告 |
| AI治理 | 流程覆盖率、典型场景节省时间、返工变化、评审覆盖率 | AI 流程记录、评审记录、自测记录 |
| 人才梯队 | 副手可承接模块数、负责人独立闭环比例、新人达标周期 | 交接记录、1对1、能力评估 |

## 7. 最小落地方式

第一周只做三件事：

1. 建立台账总表。
2. 选择最近 3 个月最有代表性的 3 条案例，补齐单条证据卡。
3. 给每条证据标注 A/B/C 可信等级和公开边界。

后续每月新增或更新证据卡，季度汇总一次。不要等到述职、晋升或求职前才集中回忆。
