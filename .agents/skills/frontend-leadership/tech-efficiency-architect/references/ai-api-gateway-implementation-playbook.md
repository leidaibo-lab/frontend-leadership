# 公司 AI API 网关落地推进手册

当多个项目分别管理模型账号、密钥、费用和调用方式时，重复接入、问题排查与权限管理会增加维护成本。AI API 网关可以集中处理这些共性工作，并为项目保留各自的授权、额度和审计记录。

本文给出建设与验收参考。能力清单和阶段目标不代表已经部署，具体范围需要结合项目数量、调用规模、供应商要求和维护资源确定。

## 网关承担的工作

- 接入：统一调用入口与鉴权约定，适配所需的模型接口。
- 成本：记录用量、预算、限额及费用归属，核对供应商账单。
- 稳定性：处理超时、限流和异常，按场景验证重试、切换与降级。
- 权限与审计：管理项目访问范围、密钥、必要日志和敏感数据策略。

统一入口仍应按项目、环境或角色分配凭据，避免多人共用一个高权限密钥。网关凭据和供应商凭据都不能直接放入浏览器等公开客户端。

## 各角色需要确认什么

| 角色 | 需要作出的决定 | 验收依据 |
| --- | --- | --- |
| 管理层与预算负责人 | 投入规模、费用归属、额度与超限处理 | 项目成本可核对，试点效果与维护成本有记录 |
| 研发及平台维护人 | 接入契约、兼容范围、维护责任和异常处理 | 目标客户端通过验证，故障可排查、可恢复 |
| 安全与合规角色 | 数据范围、模型访问、日志保留与审计权限 | 访问控制和脱敏检查通过，关键操作可追溯 |
| 业务及项目负责人 | 试点场景、质量要求、人工确认与降级体验 | 场景评测和失败处理满足实际使用要求 |

接口兼容需要验证实际使用的模型能力、流式响应、工具调用、错误格式和客户端行为，不能假设更换 Base URL 与 Key 就能覆盖全部功能。供应商切换也可能改变效果、费用和数据处理边界，应按场景评测后启用。

## 三阶段落地路径

### 阶段 1：统一入口

目标：先把 AI 调用从分散状态收口。

关键动作：

- 建立统一 Base URL 和统一鉴权方式。
- 兼容 OpenAI API 调用格式，降低业务改造成本。
- 接入至少一个主模型供应商和一个备选渠道。
- 建立项目级 API Key 发放机制。
- 记录基础调用日志、Token 用量、调用耗时和错误信息。

阶段验收条件：

- AI 调用不再依赖个人供应商 Key。
- 新项目可以通过统一网关快速接入模型。
- 能初步看到哪些项目在使用 AI、用了多少。

### 阶段 2：统一治理

目标：把成本、权限、审计和稳定性治理起来。

关键动作：

- 建立部门、项目、用户维度的额度和限流策略。
- 建立模型白名单、能力权限和敏感场景访问规则。
- 建立成本看板、调用看板、错误看板和延迟看板。
- 建立供应商健康检测、失败重试、自动切换和降级策略。
- 明确调用日志保留周期、敏感字段脱敏规则和管理员操作审计。

阶段验收条件：

- 管理层能看成本和趋势。
- 研发能查日志和问题。
- 安全合规能审计调用和权限边界。
- 业务团队能按项目透明使用额度。

### 阶段 3：统一能力开放

目标：把模型能力包装成公司内部可复用的 AI 基础服务。

关键动作：

- 逐步开放文本、代码、图片、语音、视频等多模态能力。
- 按场景沉淀推荐模型、默认参数、提示词模板和调用示例。
- 支持后台自助申请 Key、查看用量、管理项目成员。
- 支持常见业务场景模板，例如智能客服、知识问答、内容生成、数据分析和研发辅助。
- 建立接入规范、数据边界、验收指标和复盘机制。

阶段验收条件：

- AI 能力从技术组件变成可被业务团队直接申请和消费的内部服务。
- 成熟场景可以复制到更多部门和业务线。
- 公司能基于真实使用数据持续优化模型选型、预算和治理策略。

## 能力清单

### 基础接入能力

- OpenAI API 兼容。
- 多供应商模型路由。
- API Key 管理。
- 项目、部门、用户维度绑定。
- 模型别名和默认模型配置。

### 稳定性能力

- 供应商健康检测。
- 超时控制。
- 重试策略。
- 熔断和降级。
- 多账号、多渠道切换。
- 请求排队和限流。

### 成本治理能力

- Token 用量统计。
- 成本折算。
- 部门、项目、用户维度账单。
- 预算和额度控制。
- 成本异常告警。
- 高成本模型使用审批。

### 安全合规能力

- 密钥集中托管。
- 权限控制和模型白名单。
- 调用审计。
- 管理员操作审计。
- 敏感字段脱敏。
- 敏感场景拦截或审批。
- 日志保留和清理策略。

### 平台运营能力

- 用量看板。
- 成本看板。
- 错误率和延迟看板。
- 项目自助申请。
- 接入文档和示例。
- 场景模板和最佳实践。

## 关键指标

### 使用规模

- 接入项目数。
- 活跃项目数。
- 活跃用户数。
- 日均请求量。
- 日均 Token 使用量。

### 成本治理

- 总成本。
- 部门和项目成本分布。
- 单次请求平均成本。
- 高成本模型调用占比。
- 预算超限次数。

### 稳定性

- 请求成功率。
- 平均响应耗时。
- P95/P99 响应耗时。
- 模型供应商故障次数。
- 故障切换成功率。

### 安全合规

- 未授权访问拦截次数。
- 敏感请求拦截次数。
- 异常调用告警次数。
- 个人 Key 替换数量。
- 审计日志覆盖率。

### 业务价值

- AI 场景试点数量。
- 从申请到接入的平均周期。
- 场景复用次数。
- 业务侧满意度。
- 已验证 ROI 的场景数量。

## 推进会议需要确认的事项

1. 哪些项目存在重复接入、费用不明或权限管理问题，依据是什么。
2. 首阶段接入哪些场景、模型和客户端，哪些能力暂不支持。
3. 谁负责平台维护、费用审批、安全确认与业务验收。
4. 需要投入多少预算和维护时间，出现故障如何回退。
5. 哪些指标有现成基线，试点结束后如何决定扩大或调整范围。

## 建设边界

网关能集中接入与治理，但模型结果是否正确，仍需场景评测和业务确认。不能用调用成功率代替回答质量，也不能把网关上线直接计为业务收益。

日志记录应满足排查和审计需要，同时控制敏感内容、访问权限和保留时间。重试与自动切换要考虑重复执行、额外计费和输出差异；涉及实际业务操作时，需要应用侧配合幂等与人工确认。

先验证统一入口和必要治理是否解决当前问题，再按采用规模增加能力。模型会变化，长期需要维护的是接入约定、数据边界、成本记录和异常处理方式。
