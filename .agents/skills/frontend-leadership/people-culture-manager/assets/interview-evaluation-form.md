# 前端岗位分职级面试评分表

> 职级要求以[前端岗位职级标准与发展指南](../references/frontend-leveling-standards.md)为准，证据与结论口径参照[前端职级评审、定级与校准基线](../references/frontend-leveling-review-baseline.md)。
> 本表用于招聘面试记录。评分辅助比较证据，不代替逐项核验、职级判断和公司录用审批。面试安排及核验方式按招聘流程执行。

## 二、评分与证据规则

先按目标子级和主通道核对责任范围、复杂度、自主程度及影响范围，再记录六个能力维度的证据与分数。

| 评分 | 含义 |
| --- | --- |
| 1 | 有明确事实表明，该维度与目标职级要求存在较大差距 |
| 2 | 有明确事实表明，该维度部分达到要求，仍有具体缺口 |
| 3 | 有充分证据表明，该维度达到目标职级要求 |
| 4 | 达到本级要求，并在本岗位场景中体现更成熟的判断或更稳定的结果，须说明依据 |
| 5 | 达到本级要求，并有持续、充分的显著优势证据，须说明超出之处及责任边界 |
| 待核实 | 未覆盖、材料不充分或事实尚未核清；不记为低分，也不默认通过 |

- 4、5 分不自动对应更高职级，也不要求所有职级均提供组织级结果。
- 每项评价记录标准条款、本人行为、证据来源、观察周期及核验状态。仅凭候选人口述的结果标记为待核实。
- 面试官先独立记录，再汇总校准；本轮未覆盖的维度交由后续轮次补齐，不作零分或达标处理。
- 六个维度均需覆盖；不设置通用固定权重和加权总分门槛，不以某项优势抵消核心责任或共同底线的缺失。
- 区分知识问答表现、情境推演和实际履责结果。面试练习可以验证相应能力，不能单独证明长期影响或持续治理成果。
- 未使用过特定工具、未发生过重大事故，不直接构成不达标；接受责任范围和复杂度相当的等价证据，并注明认定依据。

## 三、职级责任核对

以下为责任定位摘要，具体要求逐项参照公开标准的分职级行为锚点，不能仅据摘要定级。

| 职级 | 核心责任核对 |
| --- | --- |
| P2 | 在目标和方案指导下完成明确任务、小型功能，对实现、自测与风险反馈负责 |
| P3-1 | 独立完成完整功能或小型模块的需求澄清、实现、联调和上线观察 |
| P3-2 | 对复杂模块或中型项目整体结果负责，主动形成方案、里程碑、依赖与风险控制 |
| P3-3 | 对业务领域或核心链路的持续演进、稳定运行与知识交接负责 |
| P4-1 | 技术：承担跨项目系统或关键技术项目的长期结果；管理：持续统筹稳定团队或业务单元的目标、人力、质量与成员发展 |
| P4-2 | 技术：形成多团队持续采用的领域能力；管理：通过负责人机制推动多个独立目标单元协同运行 |
| P4-3 | 技术：承担组织级关键技术领域或复杂项目组合责任；管理：在授权范围内承担跨团队关键管理领域或项目组合的持续结果 |
| P5 | 技术：负责整体前端技术战略、跨领域投资与长期业务收益；管理：负责前端组织整体目标、资源配置、组织健康与负责人梯队 |

技术通道不要求人员管理权限；管理通道不以个人代码产量或是否亲自建设平台作为达标条件。两条通道均须证明相应范围的技术判断、质量责任、协作及知识转移。

## 四、六个能力维度的面试记录

按目标子级和主通道选择问题及证据，以下问题用于追问，不新增统一技术门槛。

| 能力维度 | 追问方向 | 可核对的材料或结果 |
| --- | --- | --- |
| 业务理解与交付 | 目标和验收标准如何确定？本人如何处理范围变化、依赖与交付风险？ | 需求澄清、目标拆解、里程碑、验收及后续运行记录 |
| 技术基础与实现 | 为什么选这个方案？如何处理接口、异常和维护成本？管理岗位如何评审技术风险并推动处理？ | 实现或评审记录、测试、方案比较、技术风险处理结果 |
| 架构与工程效能 | 如何决定复用、改进或退出？收益是否经过验证，谁继续维护？ | 工程实践、采用反馈、迁移与维护记录；范围与本级职责匹配 |
| 质量、稳定性与安全 | 识别了什么风险？如何验证控制措施、发布与回滚？是否形成持续改进？ | 测试、安全检查、监控、演练、风险预防或故障复盘记录 |
| 复杂问题与决策 | 关键约束是什么？有哪些备选方案？接受什么代价，如何根据结果调整？ | 日志、实验、决策记录、资源取舍及后续验证 |
| 协作、影响与人才发展 | 如何处理不同意见并形成共同结果？如何让他人独立承接相应责任？ | 协作反馈、授权、评审、交接或共同维护记录及独立承接结果 |

每个维度复制填写一条：

- 能力维度 / 目标子级 / 主通道：
- 对应标准条款：
- 案例编号及本人责任、判断和行动：
- 可核对的结果、基线、统计周期及证据来源：
- 核验方式、已核实事实与待核实内容：
- 评分（1-5 / 待核实）及理由：
- 已确认的能力缺口 / 尚缺证据（分开记录）：
- 后续问题、核验责任人与完成时间：

AI 相关实践按本级要求核对业务规则确认、生成内容评审、测试执行、数据与权限边界及本人承担的质量责任。不以使用次数、生成代码量或声称的提效比例直接认定能力；收益需有口径、基线和观察周期。

## 五、案例、持续性与共同底线

### 核心案例记录

每个案例记录“背景—责任—判断—行动—结果—持续性”，区分本人、团队与外部条件的贡献。

| 案例编号 | 目标与约束 | 本人责任和关键判断 | 行动与结果 | 周期及后续运行 | 证据来源与核验状态 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

最低证据要求参照评审基线：

- P2：在指导下完成任务及验证的记录。
- P3-1：至少一个完整功能交付案例及上线后的运行记录。
- P3-2 及以上：采用至少两个有效独立案例、至少两个可独立验收的长期项目里程碑，或覆盖至少两个观察窗口的连续治理记录；按基线核验多次关键判断、持续性和核心责任覆盖，不将同一判断或同一结果拆分计数。
- P4：技术通道证明对应范围的跨项目技术结果，管理通道证明对应子级的管理结果；两类通道均须有知识转移与替代运行证据。P5 须证明组织级持续结果。
- 等价证据须注明对应条款及责任、复杂度、自主性、影响范围和持续结果相当的理由；不能仅因案例形式不同而否定。

允许混合项目案例与治理记录。混合证据须共同证明至少两次在不同目标或实质不同约束下的关键判断及其结果，并完成后续持续性验证；注明各项证据覆盖的责任条款，不重复计算同一次判断或同一结果。

招聘场景可通过经授权、脱敏的材料、交叉追问和合规核验形成证据。不要求候选人提供前雇主机密；无法核验的部分标明限制，不把拒绝披露机密视为能力不足。不得补造历史基线或把未来试用期计划当作已取得的结果。

### P4 及以上共同底线

各项须记录事实及证据状态，不能仅打勾或由主通道高分抵消。

| 共同底线 | 事实 / 证据编号 | 核验结论与未解决问题 |
| --- | --- | --- |
| 业务与结果判断 |  |  |
| 技术判断与长期成本 |  |  |
| 质量、稳定性与安全 |  |  |
| 协作与组织影响 |  |  |
| 知识转移与可持续运行 |  |  |

发现履历或结果造假、故意隐瞒重大风险、绕过质量安全要求、侮辱威胁或职级压制等线索时，先记录具体事实并按招聘流程核实。已核实的红线按评审基线和公司制度处理，不由其他高分抵消；未经核实的推测不得写成结论。

在责任范围、六个维度和适用共同底线核验后，选择一种职级结论：

- [ ] 达到目标职级：核心责任及适用共同底线均有充分证据，持续结果满足要求。
- [ ] 未达到目标职级：有明确事实证明核心责任或共同底线未达到，写明条款与事实。
- [ ] 证据不足：仅因材料、责任机会、归因或观察结果不足而无法确认，写明具体缺口及复核条件。

已核实的不达标事实不能用“证据不足”替代；仅缺材料也不能直接判定能力不足。面试官意见不同应保留分歧并安排复核，不能直接当作不达标结论。

- 职级结论、对应标准条款及主要依据：
- 证据充分性、持续性与本人归因说明：
- 分歧、候选人补充说明或事实更正：
- 复核人、处理结果与复核日期：

## 七、录用建议与后续安排

录用建议与能力结论分开记录，按公司招聘流程决定：

- [ ] 推荐进入录用审批：能力结论达到目标职级，岗位匹配与可培养项有具体依据。
- [ ] 补充面试或核验：尚不能形成充分结论，明确补证问题、方式与责任人。
- [ ] 不推荐当前岗位：说明已核实的能力差距、岗位不匹配或其他招聘依据。
- [ ] 建议评估其他岗位或职级：另行核对对应标准，并确认候选人意愿，不自动降级。

记录：

- 拟任岗位、工作方向、主通道与评估职级：
- 能解决的岗位问题及证据：
- 剩余风险、可培养项和支持成本：
- 入职后评价周期、实际授权、预期结果及验收方式：
- 补充核验责任人、完成时间及当前处理状态：
- 录用审批结果（与能力结论分别记录）：

最终确认由公司招聘流程指定的面试官与复核人完成。预算、名额或岗位变化不改写已形成的能力结论；试用期验证不能代替录用前对目标职级核心责任的必要核验。
